---
title: "Quickstart: path-based change detection in 5 minutes"
description: "Learn how to add Paths Changes Filter to a GitHub Actions workflow and conditionally run steps and jobs based on which files changed."
---

This guide walks you through adding Paths Changes Filter to an existing GitHub Actions workflow. By the end, you'll have a workflow that runs backend and frontend steps only when the relevant files change.

## Prerequisites

- A GitHub repository with at least one workflow file in `.github/workflows/`
- For branch-based change detection (non-PR workflows): an `actions/checkout` step before the filter runs
- For pull request workflows: `pull-requests: read` permission on the job

## Steps

<Steps>
  <Step title="Add the action to your workflow">
    In your workflow file, add a new step that references `dorny/paths-filter@v4`. Place it after your checkout step and before any steps you want to make conditional.

    ```yaml
    - uses: dorny/paths-filter@v4
    ```
  </Step>

  <Step title="Set a step ID">
    Add an `id` to the step so you can reference its outputs later. The ID can be anything; `filter` or `changes` are common conventions.

    ```yaml
    - uses: dorny/paths-filter@v4
      id: filter
    ```
  </Step>

  <Step title="Define your filters">
    Use the `filters` input to define named filters as an inline YAML string. Each filter is a name paired with one or more glob patterns. The action sets the filter's output to `'true'` if any matching file changed.

    ```yaml
    - uses: dorny/paths-filter@v4
      id: filter
      with:
        filters: |
          backend:
            - 'backend/**'
          frontend:
            - 'frontend/**'
    ```
  </Step>

  <Step title="Reference outputs in subsequent steps">
    Use `steps.<id>.outputs.<filter_name>` in `if:` conditions on any step that should only run when specific files changed.

    ```yaml
    - name: Backend tests
      if: steps.filter.outputs.backend == 'true'
      run: echo "Running backend tests"

    - name: Frontend tests
      if: steps.filter.outputs.frontend == 'true'
      run: echo "Running frontend tests"
    ```
  </Step>
</Steps>

## Complete example

Here's a full workflow that runs backend and frontend tests independently based on which files changed:

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      pull-requests: read
    steps:
    - uses: actions/checkout@v4
    - uses: dorny/paths-filter@v4
      id: filter
      with:
        filters: |
          backend:
            - 'backend/**'
          frontend:
            - 'frontend/**'
    - name: Backend tests
      if: steps.filter.outputs.backend == 'true'
      run: echo "Running backend tests"
    - name: Frontend tests
      if: steps.filter.outputs.frontend == 'true'
      run: echo "Running frontend tests"
```

## Understanding the outputs

For each filter you define, the action sets these outputs:

- **`<filter_name>`** — a string that is either `'true'` or `'false'` depending on whether any matching files changed. Use this in `if:` conditions.
- **`<filter_name>_count`** — the number of changed files that matched the filter, as a numeric string (e.g. `'3'`).
- **`changes`** — a JSON array of all filter names that matched. For example: `["backend", "frontend"]`. Use this to drive matrix jobs or downstream logic.

```yaml
- name: Print matched filters
  run: echo "Changed filters: ${{ steps.filter.outputs.changes }}"
```

<Note>
  The `pull-requests: read` permission is required when the workflow runs on `pull_request` events. Without it, the action cannot call the GitHub API to list changed files.
</Note>
