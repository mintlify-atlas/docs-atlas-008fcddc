Paths Changes Filter is a GitHub Action that detects which files changed in a pull request, branch push, or merge queue event — and exposes that information as step outputs you can reference in `if:` conditions. You define named filters with glob patterns, and the action tells you whether any matching files were modified.

## The problem it solves

GitHub's built-in path filters (`on.push.paths`, `on.pull_request.paths`) only control whether an entire workflow runs. You can't use them to skip individual jobs or steps within a workflow. Paths Changes Filter fills that gap by giving you per-step and per-job change detection.

For example, in a monorepo with a `backend/` and `frontend/` directory, you might want to run backend tests only when backend files change, and frontend tests only when frontend files change — all within the same workflow run.

## Key use cases

- **Monorepos**: Run tests and builds only for the packages that changed, reducing CI time and cost
- **Skipping slow tests**: Gate expensive integration or end-to-end tests behind file path conditions
- **Selective deploys**: Deploy only the services with code changes rather than rebuilding everything
- **Matrix jobs**: Generate dynamic build matrices that include only changed packages

## Supported triggers

Paths Changes Filter works with the following workflow event triggers:

- `pull_request` and `pull_request_target` — uses the GitHub REST API to list changed files
- `push` — uses `git diff` to compare branches
- `merge_group` — uses `base_sha` and `head_sha` from the event payload

## How change detection works

The action uses different strategies depending on the event type:

**For pull requests**, the action calls the GitHub REST API (`pulls.listFiles`) to retrieve the list of changed files. This is reliable even for PRs with a large number of commits and does not require a checkout step.

**For branch pushes**, the action runs `git diff --no-renames --name-status -z` between the relevant refs. This requires `actions/checkout` to be present in the workflow.

**For merge queues**, the action reads the `base_sha` and `head_sha` values from the event payload to compute the diff.

<Note>
  Glob matching uses [picomatch](https://github.com/micromatch/picomatch), which follows Bash-like glob rules. See [Filter syntax](/guides/filter-syntax) for supported patterns.
</Note>
