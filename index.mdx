Paths Changes Filter is a GitHub Action that detects which files were modified in a pull request, feature branch, or push — and lets you conditionally run workflow steps and jobs based on those changes. It's especially powerful for monorepos where you only want to test or deploy the components that actually changed.

## Why use Paths Changes Filter?

GitHub's built-in path filters only work at the workflow level — you can't use them to skip individual jobs or steps. Paths Changes Filter solves this by giving you per-step and per-job control based on exactly which files changed.

## How it works

<Steps>
  <Step title="Add the action to your workflow">
    Reference `dorny/paths-filter@v4` in a workflow step and define your named filters.
  </Step>
  <Step title="Define filters with glob patterns">
    Each filter is a named set of glob rules. When any matched file changes, the filter output is `'true'`.
  </Step>
  <Step title="Use outputs to conditionally run steps or jobs">
    Reference `steps.<id>.outputs.<filter_name>` in `if:` conditions on subsequent steps or jobs.
  </Step>
</Steps>

```yaml
- uses: dorny/paths-filter@v4
  id: changes
  with:
    filters: |
      backend:
        - 'backend/**'
      frontend:
        - 'frontend/**'

- name: Run backend tests
  if: steps.changes.outputs.backend == 'true'
  run: make test-backend

- name: Run frontend tests
  if: steps.changes.outputs.frontend == 'true'
  run: make test-frontend
```

<Note>
  Paths Changes Filter supports pull requests, feature branches, long-lived branches, merge queues, and local HEAD changes. See [Workflows](/workflows/pull-requests) for all supported scenarios.
</Note>
